在网络世界中，**DNS (Domain Name System)** 被称为互联网的“电话簿”。
人类擅长记忆域名（如 `www.google.com`），而计算机只认得 IP 地址（如 `142.250.190.36`）。DNS 的作用，就是当您在浏览器中输入域名时，瞬间帮您查找到对应的 IP 地址。

如果您不使用任何网络代理工具，这个查找过程通常由您的本地宽带运营商（电信、联通等）自动提供。但在开启了代理软件后，DNS 的工作机制会发生巨大的改变。

## 代理场景下的 DNS 解析路径

当您开启了 [Clash](/blog/mac-clash-verge-rev-guide/)、v2rayNG 等客户端后，客户端会接管原本的 DNS 查询请求，通常面临两种选择：

### 1. 本地解析 (Local DNS)
客户端将查询请求发给国内的公共 DNS（如 114.114.114.11 或阿里云 DNS）。
*   **优点**：解析国内网站速度极快。
*   **缺点**：如果查询的是海外特定网站，可能会遭遇**解析污染**或**DNS劫持**，导致返回一个错误的 IP 地址。

### 2. 远端解析 (Remote DNS)
客户端不直接查询，而是把域名打包，通过加密代理隧道发送到海外的[节点服务器](/blog/what-is-node)，让海外服务器代替您去查询。
*   **优点**：可以获得目标网站最真实、未被干扰的 IP 地址，同时海外服务器通常能根据其所在地，解析出距离[节点](/blog/what-is-node/)最近的 CDN 加速服务器。
*   **缺点**：每次查询都需要走跨国隧道，如果节点本身质量差，会导致首次打开网页反应迟钝。

## 现代客户端是如何处理的？

为了平衡速度与准确性，现代的高级代理客户端（结合[分流规则](/blog/what-are-routing-rules)）通常采用**“分流 DNS”**策略：
1. 先利用底层规则库快速判断域名归属。
2. 发现是国内域名（如 `baidu.com`），就用本地 DNS 解析。
3. 发现是国外域名（如 `youtube.com`），就交由远端节点解析。

## 常见的 DNS 异常现象

如果配置不当或网络环境特殊，您可能会遇到：
*   **解析错误/劫持**：原本应该去远端解析的海外域名，不小心泄漏给了本地运营商，结果返回了一个错误的甚至被植入广告的 IP。
*   **解析超时**：设置了极其复杂的 DNS 查询链，导致查询时间过长，网页迟迟不加载。
*   **Fake-IP 机制困惑**：部分高级客户端为了加速，会直接给浏览器返回一个类似 `198.18.0.x` 的假 IP 骗过浏览器，这属于正常的高级加速行为，但往往会让试图抓包排错的新手感到困惑。

如果您在浏览网页时明确遇到了涉及 DNS 的错误代码，请参阅排错指南：[DNS 解析失败怎么办？](/blog/dns-resolution-failed)。
