在理解了 [低延迟为什么不等于高网速](/blog/low-latency-slow-speed) 之后，许多用户会问：既然 Ping 值不绝对靠谱，那我应该怎么测试一个节点到底好不好用？

为了全面评估一个节点的质量，我们需要进行“轻度、中度、重度”三个梯度的立体化测试。

## 1. 轻度测试：客户端内的 URL Test (延迟测试)

这是最基础、消耗流量最小的测试方式。
多数客户端（如 [Clash](/blog/mac-clash-verge-rev-guide/), v2rayNG）都带有一个闪电图标。点击它，软件并不是去 `ping` 节点的服务器 IP，而是通过节点去尝试访问一个指定的轻量级网页（通常是 Google 或者是 `gstatic.com` 测速点），并计算返回时间。

*   **作用**：迅速剔除那些已经彻底宕机、红底超时的死节点。
*   **局限性**：只能证明这个节点“现在活着”，无法证明它能跑多快。

## 2. 中度测试：使用 Speedtest 进行吞吐量测速

如果您需要下载大文件，必须测试带宽上限。最权威的工具是 [Speedtest.net](https://www.speedtest.net) 网站或其 App。

**正确操作步骤：**
1.  在代理客户端中，选中您要测试的节点（如：日本 01）。
2.  开启系统代理，打开浏览器进入 Speedtest 网站。
3.  **核心关键**：不要直接点“GO”！先看一下页面下方显示的[测速](/blog/how-to-test-node-speed/)服务器（Server）是否位于**日本**。如果是，说明您的代理已生效；如果显示的依然是您本地城市（如北京电信），说明 [代理分流规则](/blog/what-are-routing-rules) 未将该测速网站纳入，此时测出的是您的本地网速，毫无意义。
4.  确认无误后点击“GO”，记录下载和上传数据。

*(注意：不要疯狂进行中度测速，由于跑满带宽，单次测试可能会消耗数十到上百 MB 的套餐流量。)*

## 3. 重度测试：流媒体的“统计信息” (真实体验)

测速网站的数据再好看，也不如实际体验来得真实，因为这涉及到了持续的丢包率和抖动。最推荐的重度测试方法是观看 YouTube 4K 视频。

**正确操作步骤：**
1.  使用代理打开 YouTube，找一个清晰度支持 4K (2160p) 的长视频播放。
2.  在播放画面上右键（手机端点击设置），选择 **“详细统计信息 (Stats for nerds)”**。
3.  观察屏幕左上角浮现的数据面板中，**`Connection Speed` (连接速度)** 这一项的变化。
4.  如果该数值能够稳定维持在 50000 Kbps 以上，且视频缓冲条一直在快速前进而非卡顿，说明该节点质量极高，能够完美胜任 4K 流媒体需求。
