在 [开启代理后部分网站打不开](/blog/some-sites-not-loading) 的排查中，我们提到过一种极为特殊的断网情况——**DNS 解析失败**。

区别于普通的连接超时，当 DNS 出现故障时，您的设备根本不知道该去哪里寻找目标网站，往往会在浏览器中直接抛出明确的错误代码（如 `ERR_NAME_NOT_RESOLVED` 或 `DNS_PROBE_FINISHED_NXDOMAIN`）。

请根据您观察到的具体现象进行排查。

## 现象 1：浏览器报错 NXDOMAIN

*NXDOMAIN* (Non-Existent Domain) 意味着向 DNS 服务器查询后，得到的回复是：“这个网址根本不存在”。

**排查方向：**
1.  **域名拼写错误**：请首先确认网址没有多敲一个字母。
2.  **DNS 劫持/污染**：对于某些特定海外网站，您的本地运营商可能直接切断了其解析记录并返回空值。如果在代理客户端中，该网站被错误地分配到了“直连”规则，就会触发此报错。
3.  **解决办法**：在客户端的代理规则中，尝试将该域名强制加入“走代理”的分流列表中，迫使其通过[远端 DNS 解析](/blog/what-is-dns-proxy)。

## 现象 2：DNS 查询超时

网页一直在转圈，浏览器底部显示“正在解析主机 (Resolving Host)...”，最后提示超时。

**排查方向：**
1.  **上游 DNS 宕机**：如果您在客户端中自定义了极其冷门的防污染 DNS 服务器（如某些海外小众 DoH 服务器），而该服务器国内连通率极差，就会导致所有查询超时。
2.  **解决办法**：将客户端内的 DNS 设置恢复为默认值，或改为最稳妥的公共 DNS（如 `1.1.1.1` 或 `8.8.8.8` 交由节点代解，国内交由 `223.5.5.5`）。

## 现象 3：返回异常 IP 或出现运营商拦截页面

输入网址后，网页不仅没正常打开，反而跳转到了当地联通/电信的防诈骗提示页，或者完全不相干的广告页。

**排查方向：**
这说明域名的解析请求不仅被本地网络截获，且被强行指派了一个“劫持 IP”。
*   **解决办法**：如果您使用的是支持 [TUN 模式](/blog/what-is-tun-mode) 的客户端，请开启 TUN 模式，并确保启用了 `Strict Route` 或相应的 DNS 劫持防护选项，强制所有 DNS 请求加密走虚拟网卡。

## 现象 4：浏览器能打开网页，但命令行 ping 报错找不到主机

**排查方向：**
这往往不是真正的故障！如果您使用的是 [Clash](/blog/mac-clash-verge-rev-guide/) 的 **Fake-IP（假 IP）模式**，客户端会直接丢给浏览器一个假的快速响应 IP（通常是 `198.18.x.x`）以加快网页加载，而真实的解析在远端节点进行。
此时如果在电脑系统自带的 `cmd` 里去 `ping` 这个域名，往往会因为无法穿透 Fake-IP 机制而报错。因此，在开启 Fake-IP 的代理环境下，请直接使用浏览器验证连通性。
